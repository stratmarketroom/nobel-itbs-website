# QA-005 Cookie Consent First Paint / LCP — 2026-08-31

Status: completed; Vercel Preview and Production verified

## Summary

The localized cookie banner now has a deterministic first render. On a first
visit, `pending` consent is present in the server-rendered public layout instead
of being inserted only after hydration. Accepted and declined decisions are
stored in both the existing `localStorage` contract and a necessary first-party
cookie, allowing the server to omit the banner on returning visits.

Google Analytics remains absent until explicit acceptance. Declining keeps GA
disabled, public verification paths retain their privacy-safe projection, and
the admin application still mounts neither the banner nor analytics.

The Production baseline was the earlier three-run Home mobile median:
Performance 97, LCP 2.00 seconds, Speed Index 4.01 seconds, CLS 0. In each run,
the banner paragraph became LCP after hydration.

After merge commit `d500436`, three fresh Production mobile runs recorded a
median Performance score of 96, LCP 2.13 seconds, Speed Index 4.76 seconds, and
CLS 0. The LCP element changed in all three runs from the late cookie paragraph
to the Home hero text `moves you forward`. This confirms that consent no longer
creates the Home LCP. The 0.13-second median difference is within the observed
run-to-run variability and is not claimed as a numerical LCP improvement; all
three LCP values remain below the 2.5-second laboratory “good” threshold.

## Scope

- deterministic first paint for the existing EN/UA/CZ consent banner;
- persistence and synchronization of accepted/declined decisions;
- preservation of the existing GA consent and public/admin boundaries;
- no copy, layout, analytics-event, legal-policy, or admin changes.

## Security Notes

- The decision cookie contains only `accepted` or `declined`; it contains no
  PII, identifiers, verification tokens, or analytics payload.
- It is scoped to `Path=/`, uses `SameSite=Lax`, expires after one year, and is
  marked `Secure` on HTTPS.
- It cannot be `HttpOnly` because the existing client-side consent action must
  update it immediately; this is an intentional necessary-cookie trade-off.
- GA remains basic-consent-mode only: no Google script or cookieless ping is
  initiated before acceptance.
