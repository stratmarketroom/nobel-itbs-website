## Scope

This ticket aligns the AUTH-007 static verifier and QA documentation with the
current role-safe post-login landing. It does not change authentication, TOTP
enrolment/challenge, MFA/AAL checks, role permissions, protected-data loading,
or the admin UI.

## Conflict Resolved

The original 2026-07-27 browser review recorded a successful redirect to
`/admin/users`. That was the implemented behavior at the time, but the later
role-aware Dashboard made `/admin` the correct landing for every Release 1
admin role. The production component already used `/admin`; only the static
verifier and historical QA context were stale.

## Implementation

- `verify:auth-007` now requires `router.push('/admin')`.
- The verifier explicitly rejects the obsolete `/admin/users` redirect.
- The original QA review retains its historical observation and now explains
  the current `/admin` contract.
