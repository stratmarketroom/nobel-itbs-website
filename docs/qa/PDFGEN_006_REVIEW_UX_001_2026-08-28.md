# PDFGEN-006-REVIEW-UX-001 Private Batch Review Workspace

Date: 2026-08-29

Status: implemented, locally verified, and authenticated Preview desktop/mobile
visual QA accepted

## Summary

This follow-up implements the approved human-review workflow for real generated
credential packages. The existing private batch workspace now presents stable
25-item pages, authenticated first-page thumbnails, controlled full-PDF open and
zoom actions, explicit package selection only after every PDF in that package
has been opened, and one confirmed bulk review action for the current page.

Review remains separate from activation. The existing role and MFA contract
continues to authorize Owner, Super Admin, and Credential Manager. Synthetic
PDFGEN-008 Batch A, Batch B, and Batch C remain QA-only and must never be
activated or emailed.

## Files Changed

- batch review UI and styles;
- authenticated binary request bridge for private thumbnails;
- private credential-file first-page thumbnail route;
- bounded bulk-review route, input validation, result types, and server workflow;
- focused static verifier and package script;
- this QA report and the related PDFGEN-008 dependency note.

## Database Objects

None. Bulk review reuses the existing guarded
`public.review_credential_generation_batch_item(uuid)` RPC for every explicitly
selected item, preserving its role/MFA check, package validation, reviewer,
timestamp, and per-item audit event.

## Review Contract

- one review page contains at most 25 ordered batch items;
- each generated file shows a private first-page thumbnail;
- the reviewer opens every PDF to inspect all pages and use browser zoom;
- package selection remains disabled until every PDF in that package was opened
  in the current private review session;
- the screen lists the required checks: holder, programme, credential type,
  dates, document number, QR, and layout;
- only explicitly selected generated packages are submitted;
- one confirmation records the current administrator as reviewer for up to 25
  packages;
- selection clears when the reviewer changes page;
- partial concurrent-state failures remain unreviewed and are reported without
  rolling back successfully reviewed independent packages;
- review never activates or emails a credential.

## Security Notes

- Thumbnail and full-PDF actions require the existing bearer session, active
  credential role, and MFA/AAL2.
- The thumbnail route downloads the private object server-side and returns only
  a rendered PNG with `private, no-store` and `nosniff` headers.
- Browser code receives no service-role credential, private Storage path, raw
  verification token, PDF bytes in JSON, or public PDF URL.
- Thumbnail object URLs are revoked when their page item unmounts.
- No credential status, number, PDF, activation, delivery, or Production data is
  changed by this implementation or its static checks.
- Preview configuration used only Development keys. Production Vercel and
  Production Supabase remained untouched.

## Deviations / Open Questions

- Reviewer and activator identity equality remains an approved operating rule,
  not a new database constraint in this ticket.
- The bulk route deliberately reuses the accepted per-item RPC rather than
  adding a 31st PDFGEN public database function. Independent items may therefore
  report a partial review result if their state changes concurrently.
- Google Translate occasionally left the rendered pagination label stale while
  React displayed the correct next-page item range. Acceptance used the exact
  visible document numbers to confirm the `1–25` to `26–50` transition.
- Browser console-level inspection was not available on the user-visible Chrome
  surface controlled for MFA. The authenticated UI flow, private PDF viewer,
  Vercel Ready deployment, successful route behavior, and read-only database
  audits provide the recorded acceptance evidence.
