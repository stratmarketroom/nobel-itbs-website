# PDFGEN-004 Server-Side Multi-Document PDF Generation

Date: 2026-08-25

Status: implemented and accepted locally; not yet merged or deployed

## Summary

PDFGEN-004 adds a server-runtime PDF rendering engine for one already-resolved
published Template Package. It overlays constrained text, dates, static text,
verification URLs, and QR codes onto every configured source PDF and returns an
ordered package containing exactly one primary output plus optional additional
multi-page outputs.

The ticket does not create credentials, decrypt stored token material, write to
Supabase Storage, attach `credential_files`, or expose a generation API. Those
authorization, persistence, regeneration, and private-review steps remain in
PDFGEN-005.

## Implemented Contract

- `generateCredentialPdfPackage` accepts authorized server-side values and one
  or more validated source documents with placements.
- Package validation requires one primary document and unique document IDs,
  filenames, and sort orders.
- Every source and generated PDF is parsed through the existing strict PDFGEN-002
  validator; encrypted, malformed, interactive, attached, or active content is
  rejected.
- Output page count, dimensions, and orientation must match the source.
- Every generated output returns its bytes, exact page count, size, and SHA-256
  provenance for later PDFGEN-005 persistence.
- Source and output PDF size is limited to the existing private credential-file
  limit of 20 MB per document.

## Typography and Layout

- Noto Sans weights 100-900 are loaded only from the installed server package
  and embedded into generated PDFs; no remote font request is permitted.
- Latin, Ukrainian Cyrillic, and Czech glyphs were rendered together in the
  same package.
- `single_line`, `wrap`, and `shrink_to_fit` modes are enforced.
- Required missing values, unsupported glyph/font settings, overlong words,
  insufficient height, and minimum-size overflow fail visibly with stable
  internal error codes rather than clipping text.
- Date input requires an exact ISO date and supports the constrained placement
  tokens used by the editor, including localized EN/UA/CZ month names.
- Top-left editor coordinates are transformed correctly for PDF pages with
  0/90/180/270-degree page rotation.

## QR Safety

- The renderer accepts only an absolute HTTPS verification URL without
  credentials or a fragment.
- QR is generated server-side with error-correction level Q, a four-module quiet
  zone, an embedded high-resolution raster, and a minimum printed placement of
  72 points.
- Automated scan tests decoded the exact fictional verification URL from both a
  normal page and a `/Rotate 90` page after PDF rendering.

## Tests / Verification

Passed:

- `npm run verify:pdfgen-001`;
- `npm run verify:pdfgen-002`;
- `npm run verify:pdfgen-003`;
- `npm run verify:pdfgen-004`;
- `npm run test:pdfgen-004:generation`;
- `npm run lint`;
- `npx tsc --noEmit`;
- `npm run build`;
- `git diff --check`.

The generation test creates a fictional one-page primary Certificate plus a
two-page Supplement, exercises mixed EN/UA/CZ text, localized dates, wrapping,
shrink-to-fit, multiple weights, normal and rotated page geometry, output
hashes, and exact QR round-trip decoding. It also confirms safe failures for a
missing primary output, a required missing value, text overflow, an undersized
QR placement, and a malformed source PDF.

Poppler PNG review covered all three generated pages. It initially exposed an
incorrect rotated-page overlay transform; the transform was corrected and the
complete automated and visual checks were repeated successfully.

## Security Notes

- The renderer imports Node filesystem primitives and is not browser-capable.
- It receives only the already-built verification URL, never token ciphertext,
  lookup hashes, encryption keys, service-role credentials, or Storage paths.
- It contains no application logging and does not persist generated bytes.
- Fonts are bundled in the server trace; no external document-generation vendor
  or runtime network dependency was added.
- No real learner, credential, token, template, or PDF data was used.

## Deviations / Open Questions

- No database migration, route, admin UI, Supabase mutation, or Production
  deployment belongs to PDFGEN-004.
- The test artifacts were fictional local files under `tmp/pdfs/`; they were
  removed after visual and automated acceptance and were never product data.
